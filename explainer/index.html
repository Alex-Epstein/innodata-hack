The idea

Data first, picture second, answer from code

The model only sees the picture. We hold the data it was drawn from.

structured data→PNG drawn by code →chained question→answer computed twice →7 checks→Haiku + Luna →results row

No image is AI-generated and no answer comes from a person or a model reading the picture. Because the picture is rendered from the data, we know the right answer exactly, can prove the picture shows it (pixel probes), and can rebuild the same task byte for byte from its seed. The question is built to chain reasoning: read several things off the image, apply a textbook rule (Naismith's rule, water flows perpendicular to contours, a load needs a path of closed breakers), and combine them into one exact answer.

The factory

Eight stations, one command line

Each station either adds something or throws a task out, and says why.

  1. 01

    Real data in

    Elevation from USGS 3D Elevation Program tiles (4 real places) for topo; a randomly built switchgear system for power. Stored in the repo with checksums, nothing downloaded at run time.

    gen/topo/tiles/
  2. 02

    Generate from a seed

    The seed picks the place, the window and the marks under fairness rules. The data JSON is written first, then the picture is drawn from it by code.

    factory generate --family topo --template crossings --seeds 0-9
  3. 03

    Compute the answer twice

    The answer and its reasoning chain come from the data. A second solver, written a different way, must agree or the draw is thrown away.

    solve_independent()
  4. 04

    Seven automatic checks

    Format, data first, two solvers, pixels match data, legibility, no answer leak, byte-identical rebuild. A task that fails one is out.

    factory validate --tasks …
  5. 05

    Advisory review

    Claude Sonnet reads each task like a careful human and flags ambiguity or legibility. It never changes an answer; its flags go to the human hand check.

    validate.review
  6. 06

    Evaluate Haiku and Luna

    The two models the organizers set. Same prompt, temperature 0, reasoning high, 64k tokens, cached replies, scored by the same code. Every reply and its cost is logged.

    factory eval --tasks … --out results/…
  7. 07

    Keep only what stays hard

    A question template survives only if at least one model gets 5 of 10 or fewer right, with failures that come from reasoning, not from a bad picture.

    pilot rule
  8. 08

    Anyone can rebuild it

    Judges regenerate every task from its seed and get the same bytes. A live demo builds, checks and scores a fresh task from a seed the judges pick.

    factory rebuild · factory fresh

How we got here

Seven families tried, two picked

We tested families cheaply first and kept the ones where accuracy actually drops.

Calendar v2 (Outlook Scheduling Assistant, chained rules)9/9 · 8/9Out
Subway v2 (service change + times, accessible routes, worst closure)svc 0/3 · 2/3, others 12/12Weak; the svc gap is a 2-minute trick
Gantt, ECG9/9 · 8/9, 12/12 · 12/12Out

The finding: these models read labels, do arithmetic and follow rule chains on clean layouts. They break when they have to trace a path through clutter: counting contours along a winding trail, following water around a bend, telling a crossing from a junction. That became our difficulty knob.

Why you can trust the numbers

Proof over claims

  • Two solvers. Every answer is computed twice, by different code; a disagreement discards the task.
  • Pixels match data. Probes check that the picture shows what the data says (a contour's colour, a breaker's symbol).
  • Byte-identical rebuilds. Same seed, same PNG and data, checked by SHA-256.
  • One fixed eval. Temperature 0, reasoning effort high, max 64,000 tokens, identical prompt for both models, replies cached and logged raw. Every reply in these pilots finished normally (none cut off).
  • Where it's weak (said out loud). Pilots are 10 seeds per template. Topo uses four real places, so hills repeat. Flood has 6 camps, so guessing gets about 1 in 6.
  • Sunset. On real slopes most trails climb one way, so the uphill count often equals the total count.
  • Fairness. A human baseline (a teammate solving tasks from the image only, timed) is in progress.
  • Power. Not yet hard enough to keep; we show it as a negative result.

Run it yourself

One command per station

# build 10 tasks from seeds 0-9, check them, score both models
uv run python -m factory generate --family topo --template crossings --difficulty 3 --seeds 0-9 --out tasks/pilot_topo_crossings
uv run python -m factory validate --tasks tasks/pilot_topo_crossings
uv run python -m factory eval     --tasks tasks/pilot_topo_crossings --out results/pilot_topo_crossings
# judges: regenerate every task from its seed and compare bytes
uv run python -m factory rebuild  --tasks tasks/pilot_topo_crossings
# live demo: a judge picks a seed; build, check and score one fresh task
uv run python -m factory fresh    --seed 7 --show
